# 从离线生成器到连接即生成

目标用户流程：连接相机，识别精确型号和固件版本；匹配已验证采集适配器；采集本地分区文件；由生成器验证、构建并启动；显示本次实际达到的能力。

当时实现只有最后半段。首次授权、设备模式变化和异常恢复需要在未来接入界面前另行设计；不要自动调用独立的维修或服务测试流程。

## 采集器的文件交接

采集器应先在临时目录写入 `nflashaN.bin`，完成每个文件后记录大小和 SHA-256。只有采集完成、退出状态有记录后，才交给离线生成器。当前 CLI 默认按固件指纹自动选配方，显式 `--profile` 则是用户选择；这两者都不能替代 USB 层的真实机型与版本查询。

后续采集清单应至少包含：schema 版本、经查询确认的型号／固件、采集器版本、文件名／长度／SHA-256、成功与缺失分区、完成状态、退出检查结果。不要保存序列号、认证材料或密码到分享用的报告。报告和设置／日志分区默认本地保存。

生成器不持有 USB 句柄，不导入采集器，也不负责机身恢复。离线生成器本身不实现 USB 自动发现、维修模式进入、认证、密钥推断、相机文件采集或自动重试。

## 新机型适配

1. 先添加候选 profile；仅允许清点输入。
2. 用该机型自己的固件核对 CPU／机器模型、主启动对、文件系统和模块。
3. 找到补丁所需符号、指令与文件系统位置，建立版本配方和完整性条件。不能仅因 CPU 相同就复用硬编码地址。
4. 用固件副本通过生成与产物校验，再单独做启动验收。
5. USB 采集器另行验证身份匹配、错误处理、退出恢复，再接入同一条离线流水线。

共享的是提取、校验、组盘、构建、报告和启动机制；差异集中在配置、补丁配方与采集适配器。现有 `a7m3-4.03` 是第一条具体配方；出现第二条真实配方后再抽象共用补丁接口。

## 能力状态

- `candidate-needs-offline-firmware`：有机型入口，未具备生成配方。
- `upstream-reported-shell`：上游报告该配方启动到命令行，本地尚未复现。
- `generated-not-boot-verified`：本次生成完成，未验证启动。

后续启动验收应检查：内核版本输出、分区识别、关键挂载点、BusyBox 可执行命令。菜单、显示和拍摄链分别验收，不能以 shell 成功代替。当前代码不会自动把启动状态提升为已验证。
