# Sony VM：先实现 R3A，再整理多机型接入

> **归档状态（2026-11-04）：** 维护者已停止后续开发。下文保留归档前的计划快照；其中的“当前”“下一步”和任务状态是历史记录，不代表项目仍在推进。原始固件、私有实验盘和完整日志没有发布。

更新：2026-11-01。当前开工入口是 [V002：R3A 首次离线启动验证](validations/V002-r3a-boot.md)。[E001 多机型配置任务包](enablers/E001-profile-registry.md)保留并后置，代码尚未按本计划改造。

## 1. 当前目标与后续目标

当前专注用户自己的 ILCE-7RM3A：用已读出的固件，在 QEMU 中逐步实现启动、命令行、主程序、菜单及基本输入。先走通本机路径，再根据实际差异设计通用结构。

R3A 按四个里程碑记录：

| 里程碑 | 可观察成果 | 说明 |
| --- | --- | --- |
| R0：进入内核 | 原固件内核日志，能确认执行位置 | 首个启动成果 |
| R1：原固件命令行 | 关键分区挂载，可执行命令和读取程序目录 | 可开始研究用户态，不代表完整相机 |
| R2：主程序 | 启动相机主程序，记录加载链与具体设备阻塞 | 存活或绕过 abort 不等于行为正常 |
| R3：菜单与输入 | 原生菜单显示，并响应一种按键输入 | 显示和输入分别验证，缺什么明确标记 |

按 R0→R1→R2→R3 推进；未知外设逐项研究，不预设全部可行或承诺固定工期。成像、拍摄、FL 风格滤镜和触摸另行验证。显示研究若卡住，先定位阻塞，不自动改做多机型架构。

后续产品目标保留：别人连接自己的已支持相机 → 识别 → 采集退出 → 校验 → 创建模拟器 → 离线启动；贡献者可以增加新机型。R3A 研究版可先独立开放复现，不等待完整通用平台。

## 5. 为后续适配保留的最小边界

现在保留现有 `profiles/` 和第三方来源记录；R3A 的输入、实验参数及补丁依据独立保存。不扩展注册框架、通用采集器或动态插件系统。

将来分别整理机型版本配置、采集适配、构建配方和 QEMU 平台。USB 在宿主机执行，QEMU 可在 Linux 容器运行，通过本地文件交接。不同机型可复用平台，补丁按固件验证。

整分区哈希用于本地完整性；跨机兼容性需验证关键文件和补丁条件。现有 A7M3 严格校验不放宽，R3A 也不通过改型号或关闭校验套用 A7M3 配方。

## 6. 开发节奏与归档时状态

项目开发时采用教学模式，每次一个可验收任务：先解释原理，再分析证据与下一阻塞。学习顺序沿 R3A 主线：固件文件 → 内核与 initrd → 加载地址和串口 → 挂载／驱动 → 主程序 → 显示／输入。

`ai-project-facilitator` 用于准备与审查任务；`work-item-manager` 留给后续明确交给 AI 自主执行且已准备好的 E/F，不用于当前 V 研究。

归档时，V002-T01 已完成，T02—T04 部分推进。隔离探针观察到目标路径请求 128 KiB `MAP_SHARED`，而重定向后的 `/dev/null` 返回 `-ENODEV`；匿名映射对照仅证明 Linux 接受相同长度的内存请求。Sugilite ioctl、事件、共享区语义及运行时绘图调用链仍未确认。曾建议继续检查 `GRM_gpermFillrect`／`GRM_gpermRectblit` 的运行时可达性，再评估用户态软件绘图或最小设备桩；该建议没有执行，项目也未选择实现路线。完整 GPU 模型缺少寄存器、命令与中断协议证据。
